# 効果音

Web Audio で合成する。外部の音源は 1 つも使わない。

理由は 2 つ。アセットのライセンス記録（`CLAUDE.md`）を増やさずに済む。そして大気の LUT 4.1 MB を読み込む起動時間に、音声ファイルを積み増さずに済む。`assets/CREDITS.md` に行が増えないのはこのため。

## 音は目で見えないので波形を測る

ノードが繋がっただけで振幅が 0、という状態は画面を見ても分からないしスクリーンショット回帰にも写らない。`?audioprobe=1` で `OfflineAudioContext` に書き出し、rms とピークを測って `hook.audioProbe` に置く。`?bench=` や `?sweep=1` と同じ、計測のためのモード。

実時間は待たない。1.5 秒ぶんの合成がミリ秒で終わる。

`synth.ts` の関数が `AudioContext` ではなく `BaseAudioContext` を受けるのはこのため。狭めると `OfflineAudioContext` を渡せず、この検査が書けない。

実測値（2026-08-31）。

| 音 | rms | peak |
|---|---|---|
| 爆発 | 0.0580 | 0.7098 |
| ミサイル発射 | 0.0204 | 0.2359 |
| ミサイル警告 | 0.1894 | 0.3867 |
| 機銃 | 0.0945 | 0.4706 |
| エンジン | 0.0439 | 0.2078 |
| 全部同時 | 0.5850 | 0.9800 |

## クリップは 3 段構えで防ぐ

**個々のゲインを詰めるだけでは足りない。**爆発は当初 peak 1.18 で、単体でクリップしていた。しかも 1 フレームに 2 発まで重ねる。その裏で機銃とエンジンが鳴り続けている。全部が同時に立つ瞬間の振幅は予測できない。

音量を下げて逃げると、単発が聞こえないほど小さくなる。

1 段目は個々のゲイン。爆発を 0.9 から 0.54 へ、低域の衝撃を 0.8 から 0.48 へ下げた。単発 peak が 1.18 から 0.71 になった。

2 段目は `DynamicsCompressorNode`。しきい値 −6 dB、比 12、膝 0 でリミッタとして働く。立ち上がり 3 ms は爆発の 12 ms に間に合う。

**それでも足りなかった。**`DynamicsCompressorNode` はルックアヘッドを持たないので、瞬間的なピークを通す。全部が同時に鳴る場合を 8 回測ったうち 2 回が 1 を超えた（1.0166 と 1.0535）。波形は `Math.random()` のノイズなので、引きによって変わる。

3 段目がソフトクリップ（`WaveShaperNode`）。しきい値 0.7 までは傾き 1 のまま、そこから上だけ `tanh` で丸めて 0.98 へ漸近させる。**出力が 0.98 を超える経路が無い。**8 回測って 8 回とも 0.98 だった。

全体に `tanh` を掛ける形は採らなかった。通常の音まで 8% ほど痩せる。

## オーバーサンプリングがかえって悪化させた

`WaveShaperNode.oversample` を `'4x'` にすると、内部で 4 倍にしてからカーブを適用し、元へ戻す。**その戻すときのフィルタがリンギングを生む。**0.98 未満に丸めたはずの波形を 1 の上へ押し戻してしまう。

実測で、`'4x'` にしたら 8 回すべてが 1.04〜1.07 になった。切る前（8 回中 2 回が超過）より悪い。歪みの少なさよりクリップしない保証を取り、`'none'` にした。

## 上限を 1 にすると測れなくなる

ソフトクリップの上限を 1 にすると、`tanh` が 1 へ漸近する部分は `Float32Array` へ入れた時点でちょうど 1.0 へ丸められる。実測で 8 回すべてが 1.0000 だった。

1.0 はサンプル値の有効範囲の内側なのでクリップではない。だが上限に触れているかどうかを測って区別できない。0.98 にすれば、1.0 に達していないことをそのまま確かめられる。

カーブの計算は `WaveShaperNode` から切り離して `softClipCurve` にした。「必ず 1 を下回る」「小信号は素通し」「単調」「奇関数」という性質は、ブラウザを立ち上げずに確かめられるべきもの（`tests/audio/softClip.test.ts`）。

## sim には触らない

`Combat` が持つ単調増加のカウンタの差を見る。`roundsFired` / `explosionCount` / `missilesFired`。sim にコールバックを生やすと、そこから DOM や Web Audio へ手を伸ばす道ができる。`layering.test.ts` の規約が形骸化する。

**やり直しで 0 へ戻る。**`R` を押すと `World` が作り直されてカウンタが 0 になる。素直に引くと大きな負の数になり、回数として扱うとループが回らないか異常な値になる。負の差はそのフレームを鳴らさない扱いにした。

やり直しそのものを音のきっかけにはしない。鳴らす対象が無く、撃ってもいない弾の音を出すことになる。

## 機銃は 1 発ずつ鳴らさない

M61A1 は毎分 6,000 発（`docs/weapons.md`）で秒 100 発。1 発ごとに音源を作ると 1 秒に 100 個で、聞こえ方も実物と違う。個々の発射音は分離せず連続した唸りになる。

ノイズを帯域で削り、発射速度 100 Hz の鋸波で振幅変調を掛ける。これが唸りの正体。撃っているあいだ 1 本鳴らし、止まったら 30 ms でフェードして切る。すぐ 0 へ落とすとプツッと鳴る。

## AudioContext は START に紐づける

ブラウザの autoplay 制限で、ユーザ操作を経ずに作った `AudioContext` は `suspended` のまま音が出ない。タイトルの START が受け皿になる（段 7 で `onStart` を開けてあった）。

**作れなくても落ちない。**古いブラウザ、音声デバイスが無い、ポリシーで拒否といった場合に `null` を返す。音は無くても遊べる。

`?sound=0` で鳴らさない。キャプチャモードの既定でもある。1 枚描いて止まるので鳴らす意味がなく、`AudioContext` の生成が待ち時間になる。
