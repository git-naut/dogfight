# 0003 雲のレンダリング

2026-08-17 決定。Phase 3。

原理と実装の対応は `docs/clouds.md` にある。ここには判断とその根拠だけを残す。

## 決めたこと

ボリュメトリックレイマーチングを自前で実装し、結果を `AerialPerspectiveEffect.overlay` へ渡して大気と合成する。ノイズは起動時に GPU で焼く。時間的アップサンプリングは採らない。

## 大気との合成点

`AerialPerspectiveEffect` のシェーダに `overlay` の入力があり、乗算済みアルファで合成される。後段で自前合成すると in-scatter と透過の順序が崩れるので、この差し込み口を使う。合成の順序はライブラリ側が持つ。

## ノイズを焼く方式と解像度

3D ノイズをファイルとして配信する案は採らなかった。128³ の RGBA8 は 8.4 MB あり、大気の LUT 4.12 MB に上乗せするには重い。ハッシュ関数だけで作れるので、起動時に GPU で焼けば転送量はゼロで済む。

解像度は実測で決めた。CI のソフトウェアレンダラでページ読み込みが 64³ で 3.5 秒、96³ で 6.9 秒、128³ で 9.0 秒。雲なしの基準が 2.5 秒。E2E は 20 回以上ページを開くので、128³ の 6.5 秒増は許容できない。64³ を採る。

実機の GPU には余裕があるが、CI と違う値にすると基準画像が一致しない。1つの値で通す。

## ハッシュを整数演算にする

`fract(sin(x) * 43758.5453)` 系の定番は使わない。実測で SwiftShader と llvmpipe のノイズ平均が 0.621 と 0.657 に分かれた。`sin` の精度が実装ごとに違い、その差が `fract` で増幅される。

PCG の整数ハッシュへ替えて一致した。32bit 整数の乗算とシフトは仕様上どの実装でも同じ結果になる。GLSL ES 3.00 が要るので、ノイズのマテリアルは `GLSL3` で書く。

これは Phase 0 から守ってきた決定論の前提に直接効く。スクリーンショット回帰はローカルと CI で同じピクセルが出ることを土台にしている。

## 時間的アップサンプリングを見送る

当初の計画では 1/4 解像度でマーチして時間方向に収束させる予定だった。採らない。

16 フレームほどかけて収束させる手法で、1 フレームしか描かないキャプチャモードと噛み合わない。モーションベクタと履歴の棄却も要り、実装量が大きい。

代わりに空間的な削減とし、Bayer の秩序ディザでバンディングを散らす。白色ノイズでずらすと画素ごとにばらけて斑点になった。実測を見て秩序ディザを選んだ。必要になったら次の Phase で足す。

## 品質プリセットの雲の列を差し替える

当初の表は Low がビルボード、Medium がメッシュクラスタ、High 以上がレイマーチだった。雲の実装を3つ抱える形になり、工数として見合わない。1つのレイマーチで解像度とステップ数だけを段階にする。

## 実装中に直したこと

**消散係数。** 0.045 では 600 m の 1 歩で光学的厚みが 27 になり、1 ステップで真っ白に潰れた。0.012 へ下げた。

**位相関数のスケール。** 全立体角で積分すると 1 になる定義をそのまま使うと、値が 0.03 前後にしかならず空より暗い雲になった。4π を掛けて等方散乱を 1 とする相対値に直した。

**多重散乱。** 単一散乱だけだと雲が灰色に沈む。オクターブごとに消散を弱めて重ねる近似を入れた。

**powder 項。** 密度に歩幅をメートルで掛けていたため 1 歩で飽和し、常に 1 になって効果がゼロだった。密度そのものから作る形へ直した。

**雲量のしきい値。** 気象マップを焼く時点と実行時の両方で掛けていた。0.4 で快晴、0.55 で全面雲という段階のない応答になった。しきい値を実行時の一箇所へ集約し、FBM の値域も 0 から 1 へ引き伸ばした。

**雲影を焼く順序。** `CloudsPass.render()` の中で焼いていたが、地面を描くのは前段の `RenderPass` なので反映が次のフレームになる。キャプチャモードは 1 フレームしか描かないので永久に反映されなかった。`composer.render()` より前へ移した。

**古い dist で検証していた。** 手動で起動した `vite preview` が残っていると、
Playwright の `reuseExistingServer` が既存サーバを再利用してビルドを飛ばす。
古い成果物に対してスクリーンショット回帰をかけることになり、検証そのものが
嘘になる。`reuseExistingServer: false` にして、毎回ビルドさせるよう変えた。

**onBeforeCompile の二段差し替え。** 地面へ雲影を差し込むのに `onBeforeCompile` を後から差し替えたら、まったく効かなかった。three がキャッシュキーでプログラムを再利用するため。`needsUpdate` を立てても直らない。差し込みは1回で済ませる。

## 解像度は実機の計測で決めた

実機（Intel Arc 140V、1080p）で 1/4 解像度のとき、フレーム全体が 5.2 ms、
うち雲パスが 2.7 ms。余裕が 11.5 ms あった。

`?cloudScale=1` で全解像度にすると雲パスが 41.6 ms になった。画素数 16 倍に
ちょうど比例していて、純粋に画素数で決まる負荷だと確認できた。

ここから 1/2 解像度なら雲 10.8 ms、合計 13 ms 前後と外挿できる。High を
1/2 に上げた。Ultra は 5/8 で 22 ms 前後の見込みとし、60fps は狙わない
位置づけにした。

全解像度でも粗さが残ったのは別の原因だった。Bayer の 4x4 では段階が 16 しか
なく、雲の内部に横縞が出る。8x8 の 64 段階へ上げて崩した。解像度と
ディザの段階数は別の問題で、片方だけ上げても解決しない。

## GPU 時間の計測を入れた

実機は vsync で 60fps に張り付くので、余裕が読めない。`EXT_disjoint_timer_query_webgl2` で GPU のフレーム時間を測り、`?debug=1` の表示に出す。拡張が無い環境では伏せる。

雲のレイマーチは解像度とステップ数の調整余地が大きいので、実測なしでは決められない。

## 地面のアルベドと雲影の強さ

雲影は `mix(0.42, 1.0, shade)` で掛ける。真っ暗にはしない。空からの散乱光は雲があっても届くため。高度 2,000 m から見下ろすと大気の霞が上に乗るので、地上で見るほどのコントラストにはならない。
