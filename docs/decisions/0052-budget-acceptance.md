# 0052 予算の検収と、海を分割 0.5・カスケード 3 にした判断

2026-11-05 決定。Phase 11 の段 S5。実測は `docs/measuring.md` の「段 S5」。

## 判定の線

CP1（2026-10-25）の全体の予算、合計の中央値 ≤13.0 ms・95% ≤15.0 ms・降格なしで判定した（ユーザーの決定、2026-11-03）。計画書の完了の判定にあった「刷新後の GPU 中央値 ≤ 刷新前」は外した。CP1 で余白の半分を使うと決めたので、2 つは両立しない。前後の差は数で残す。

フレーム合計の最大 ≤16.7 ms も絶対の線にしなかった（同じ日の決定）。刷新の前の版でも 16〜24.9 ms のコマがあった。前後で悪くなっていないことを見る。

判定に使う構図は段 S0c と同じ 6 条件で、catapult-launch は参考にした（ユーザーの決定、2026-11-04）。射出は刷新の前でも 12.5〜13.0 ms で、線ぎわだった。

## 予算の配り直し

海（計算＋海面）を 5.5 ms から 7.4 ms にした（ユーザーの決定、2026-11-04）。層の雲で浮いた約 1.9 ms を回した。判定の計測の海の合計は low-pass で 5.09 ms で、元の 5.5 ms の内にも入っている。

## 海を軽くした

段 S4d の割れ目の直し（ADR 0047）で近くのパッチが本来の細かさになり、GPU が 1 コマ約 13 ms を越えて low-pass でコマが落ちた。軽くする手を 4 つ試し、ユーザーが分割距離 0.75 → 0.5 とカスケード 4 → 3 を選んだ。medium も段の順を保つため同じ値にした。FFT 128 は効きが最大だったが近くの波の形が変わり、泡 0 段は喫水線の泡が消えるので採らなかった。

## 計測の作法で変えたこと

計測の記録に跳ねたコマの内訳を残し、門を厳しくした（終わりの 1 分平均を 1 未満、最中の最大を 1.5 未満）。門は WSL の負荷しか見ないので、Windows 側の揺れは除けない。前の版と今の版が同じ巡で崩れたら、その巡は両方とも除く。
