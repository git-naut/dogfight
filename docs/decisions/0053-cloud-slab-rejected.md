# 0053 積雲に厚みを持たせる板を試し、採らなかった判断

2026-11-05 決定。Phase 11 の段 S6。実測は `docs/measuring.md` の「段 S6」。試した実装の差分はリポジトリに入れていない。控えは `~/.claude/plans/dogfight-ocean-ref/measure/s6/s6-cloud-slab-trial.patch`（1,161 行）。

## 何を直したかったか

段 S4b の絵の承認で指摘を受けた。上から見た積雲は平らで陰影が薄く、遠くは横に引き延ばされて見える。段 S4d で自己影を強める手と画素の幅を和らげる手を試した。どちらも効きが小さいか、縁が階段状になった。見かけの厚みは S5 のあとで諮ると決めていた。

## 試した形

低い積雲（1.5 km）だけを高さ場の板にした。2D の密度をそのまま雲の高さに使い、雲底からの高さが厚み × 密度より低い所を雲の中とした。厚みの最大は 0.6 km で、晴天の積雲は数百 m〜1 km 程度という一般の知識からの推測で出典はない。視線を板の中で等分に歩き、最初に雲へ入った歩と前の歩の間をはさみうち法で 2 回詰めた。高層雲（4.5 km）は 2D のままにした。

GPU の式は WGSL で書き、CPU 参照と 256 本の視線で突き合わせた。当たりと外れの食い違いは 0、当たった距離の差は距離で割って 2.7e-4、絶対の差は最大 2.2 m だった。

途中で 3 回、形を変えた。

1. 雲底を 1.5 km に置くと、level の台本（2,000 m）が板の中を飛ぶ。カメラの点が雲の中と判定され、すべての視線が距離 0 で当たって雲が消えた。ユーザーの決定で、頂を 1.5 km、雲底を 0.9 km にした。台本や遊びの高さと雲の上下の関係は平らな層と同じになる。
2. 距離の 2 乗で刻むと、遠くの 1 歩が数 km になり、等高線のような縞が出た。等分に替え、詰め直しを足した。それでも下から浅く見上げると雲の横腹に水平の縞が残り、歩き始めを画素ごとにずらすと斜めの網目に変わった。16 歩でも残った。ユーザーの決定で、カメラが頂より上で見下ろす視線だけを板にした。
3. 頂のすぐ上から浅く見下ろす構図でも網目が出た。1 歩の長さが 0.4〜0.8 km の間で平らな層へなじませる形を試した。遠くの網目は消えたが、近くの盛り上がった雲の縁に 8 歩の網目が残った。近くは立体、遠くは平らという形の混在も出た。

## 費用

実機（Arc 140V、high、1600×789・倍率 1.5、上から見下ろす level・16 時）で平らな層と交互に 4 回ずつ測った。

| 歩数 | 合計の中央値 | 雲の群の中央値 |
|---|---|---|
| 平らな層 | 10.91〜10.94 ms | 0.66〜0.68 ms |
| 8 歩 | 11.00〜11.86 ms | 2.23〜2.33 ms |
| 16 歩 | 13.14〜13.59 ms | 3.82〜3.90 ms |

16 歩は CP1（合計の中央値 ≤13.0 ms）を越える。8 歩は全体の予算の内だが、雲の予算 0.8 ms の約 3 倍になる。

## 判断

採らない（ユーザーの決定、2026-11-05）。予算に収まる 8 歩では、縁の網目と形の混在が残る。既定の絵は動かしていない（exact 47 枚、差 0）。

高さ場の板は、雲の面を飛び越えない細かさで歩くことが前提になる。浅い視線では板の中の道のりが十数 km になり、雲の大きさ（1〜2 km）に対して歩数が足りない。作り直すなら、雲の無い所を大股で飛ばす歩み方か、体積の雲（段 S4b で消した）のような別の作りを考える。その時は控えた差分の CPU 参照と突き合わせの道具を流用できる。

上から見た積雲の平らさと、遠くの横への引き延ばしは、持ち越しの差として残す。
