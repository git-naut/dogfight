# 0054 Phase 11 の全体: 空・海・雲を web-ocean の技法へ置き換えた

2026-11-05 決定。Phase 11 の段 S7。枝 `phase-11`（main の 79ad016 から切った）。各段の決定は ADR 0044〜0053 にあり、ここは全体の地図と、段をまたぐ決定と、持ち越しの差だけを残す。数式と実装の対応は `docs/sky.md`・`docs/ocean.md`・`docs/cloud-layers.md`、実測は `docs/measuring.md` の段 S0〜S6。

## 何を替えたか

ユーザーの指示で、地形・海・雲・空の描画を web-ocean（Noniv/web-ocean、MIT、a07c7fd）の技法へ刷新した。リソースの予算を実測で決め、その内に収めた。

| 描画 | 前 | 後 | 決定 |
|---|---|---|---|
| 空と霞 | takram（`@takram/three-atmosphere`、EXR の LUT） | 自前の Hillaire 2020（TSL の LUT、起動時と毎フレームに焼く） | 0044・0045 |
| 海 | 板の海と正弦波 | FFT の海（high は 3 × 256、CDLOD、LEAN・きらめき・泡） | 0046〜0049 |
| 雲 | 体積の雲（雲影マップ・ノイズの焼き込み） | 1.5 km の積雲と 4.5 km の高層雲の 2 枚の層 | 0050 |
| 地形 | 島（高さ場） | 無し。地面は海面（高度 0）だけ | 0051 |
| 描画の経路 | WebGPU と GLSL（WebGL）の 2 本 | WebGPU だけ。無ければ起動前に利用者向けの文言で止める | 段 S1 |

## 段の順と、計画から変えたこと

計画の段は S0 計測 → S1 退避路の削除 → S2a・S2b 大気 → S3 FFT の基盤 → S4a・S4b 海 → S5 予算の検収 → S6 巻雲 → S7 後片付けだった。実際は次のように変えた。どれもユーザーの決定。

1. 体積の雲を残す計画だったが、S4a のあとで雲も web-ocean の 2 層へ置き換えた（10-29）。段 S4c を足し、巻雲の段 S6 はそこに吸収した。
2. 島は海岸の係数まで作る計画だったが、海の予算を超えたのでゲームから消した（10-29、段 S4b）。
3. 段 S4b の絵の承認で見つかった網目と積雲の平らさを直す段 S4d を、S5 の前に足した（10-31）。
4. 空いた段 S6 では、積雲の見かけの厚みを試し、採らなかった（ADR 0053）。

基準画像の撮り直しは計画で最大 3 回としたが、4 回になった。#1 は S2b（空）、#2 は S4b（海と雲の切り替え）、#3 は S4d（網目と継ぎ目）、#4 は S5（海を軽くした）。どれも段の中でユーザーが決めた。

## 予算（CP1）と配り直し

段 S0 で、刷新の前の版を実機で測った。Intel Arc 140V、high、1600×789・倍率 1.5 の level で、合計の中央値は 11.56 ms。ユーザーは CP1 として余白の半分を使うと決めた（10-25）。合計の中央値 13.0 ms 以下、95% 15.0 ms 以下、降格なし。

群ごとの予算は段の途中で 3 回配り直した。

| 群 | CP1（10-25） | 10-29 | 10-30 | 11-04 |
|---|---|---|---|---|
| 海（計算＋海面） | 3.5 ms | 5.5 ms | 5.5 ms | 7.4 ms |
| 空と霞 | 2.0 ms | 0.5 ms | 0.5 ms | 0.5 ms |
| 雲 | 2.7 ms | 2.7 ms | 0.8 ms | 0.8 ms |
| 地形 | − | 0 | 0 | 0 |

段 S5 の判定（11-05 未明、PC を使わない時間）では、6 条件とも CP1 の内だった。level・low-pass・enemy-eight の 16 時と 18.3 時で、合計の中央値は 9.65〜11.79 ms、95% は 14.78 ms 以下。射出は参考の構図にして 12.66 ms 以下。公開ページでも 7 条件とも内（中央値 8.49〜10.72 ms）。表は `docs/measuring.md` の段 S5。

## 段をまたいで守った決まり

新しい描画は切り替えの口の裏で作り、既定の絵を動かさないまま CPU 参照と突き合わせた。突き合わせは `?gpu=2` の自己診断で、LUT は各色の最大値基準 2e-3、天空光 1e-3、海 1e-4、雲の縁 1e-3 で縛った。既定に切り替える段でだけ撮り直し、exact（47 枚の画素一致）で確かめた。

出典の無い値は ADR に「推測」と書いた。空の正しさは takram ではなく、球の大気のモンテカルロ法の正解と比べた。関門の幅は、太陽の高さ 25 度以上の 3% と、未満の 5%（ADR 0044）。takram の天空光は昼に正解の 1.24〜1.61 倍明るかった。

## 持ち越しの差

直していないもの、測っていないものを残す。

- 上から見た積雲が平らで、遠くは横に引き延ばされて見える（ADR 0053 で板を試して採らなかった）。
- enemy-eight は 60 fps に届かない回がある（段 S0d。刷新の前は 51〜57 fps、後は 54〜59 fps）。原因は確かめていない。
- 測り始めて数分たつと、GPU 全体の遅くなる形がある。熱か電力の上限と見ている。確かめてはいない（ADR 0052）。
- `?smaa=0` で画面全体がほぼ黒くなる（段 S4d で見つけた）。
- 撮影のたびに WebGPU の警告「Draw with an index count of 0」が 1 回出る（段 S4c から）。
- 低い太陽で、Hillaire の天空光がモンテカルロ法の正解から約 4% ずれる（近似に固有と推測）。
- 露出 6 とブルームの閾値は takram の光の尺度で決めた値のまま。自前の空は直達光の尺度を takram にそろえた（ADR 0044）。
- 月は描かない（段 S2a のユーザーの決定）。

段 S7 で文書を書くときに、次の 3 つを見つけた。どれも絵が動くので S7 では直していない。

- 海面の空の映り込みが、傾きの広がりでミップを選んでいない。`oceanSurface.ts` は広がりを渡しているが、`pipeline/nodeScene.ts` と `pipeline/node.ts` の `skyRadiance` が受け取らずに捨てている。ADR 0048 の意図と違う。
- 風の斑はカスケードの 4 段目以降にしか掛からない。段 S5 で high と medium もカスケード 3 本にしたので、low・medium・high では斑が効かず、ultra でだけ効く。段 S4d の遠くで寄せる直し（`oceanTileFade`）も同じ。
- 層の雲の画素の大きさを全解像度の高さから求めているが、雲は半分の解像度で焼いている。意図したものかは確かめていない。
