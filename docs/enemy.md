# 敵機

`src/sim/enemy.ts`、`src/render/enemyView.ts` の中身を、原理と実装の対応で説明する。機体そのものの取り込みは `docs/aircraft.md`。

敵機は `Aircraft` を保有する。標的機（`src/sim/target.ts`）が決められた軌跡を飛ぶ剛体なのに対し、敵機は自機と同じ飛行モデルで飛ぶ。**引きすぎれば失速し、低空で引けば地面に当たる。**「旋回すると速度が落ちる」という空戦の核が敵の挙動に出るのはこれのおかげで、代わりに「AI が自滅しない」ことを検証しないといけなくなる。

## 撃たれる側と見える側を分ける

武装が相手に求めるものを測って書き出した。

| 使う側 | 読むもの |
|---|---|
| `Combat.resolveHits` | `position` `orientation` `alive` `damage()` |
| `Lock.pick` / `Lock.measure` | `position` `velocity` `alive` |
| `Missile.guide` / `checkFuze` | `position` `velocity` `orientation` `alive` |
| `Combat.updateDlz` | `speed` |

`hitbox.sweptHitsAircraft` は位置と姿勢を生で取るので、もともと型に依らない。だから 6 つの口を `Combatant` として切り出し、`Target` と `Enemy` の両方が満たす形にした。`Combat` の型を差し替えるだけで済む。当たり判定とロックとミサイルには触らない。

そこから 1 段さらに分けた。**敵 AI が追う相手は、殴れる必要がない。**

```ts
export interface Tracked {
  readonly position: Vec3
  readonly velocity: Vec3
  readonly orientation: Quat
  readonly speed: number
  readonly alive: boolean
}

export interface Combatant extends Tracked {
  damage(amount: number): boolean
}
```

自機はいま追尾される側だがダメージを受けないので、`damage()` を持たない `Tracked` にしか当てはまらない。自機が撃たれるようになったら `Combatant` へ広げる。

`World` は `targets` と `enemies` を `combatants` として 1 本の列に並べ、`Combat` へ渡す。**添字はこの列の順で、標的機が先に来る。**HUD のロックボックスは `lock.index` で補間した位置を引くので、この順を知っている必要がある。

## 継承しない

`Enemy` は `Aircraft` を継承せず保有する。継承すると AI の状態が飛行状態と混ざり、`AircraftSample` の意味も曖昧になる。`position` などは委譲する。

`step()` は AI が作った `InputState` を `Aircraft.step` へ渡す形にした。接続点は自機と同じで、キーボードとリプレイに次ぐ 3 番目の入力の作り手になる。

```ts
step(dt: number, player: Tracked): void {
  this.aircraft.step(this.decide(player), dt, this.stepOptions)
}
```

G 制限と失速の回避は AI に持たせない。`applyAoaLimiter` と `gLimitedPitchRate` がすでに `Aircraft` の中で効いているので、AI がフルに引いても機体側が絞る。AI は「引きたい量」を出すだけでよい。

## 墜落を撃墜と同じに扱う

```ts
get alive(): boolean {
  return this.integrity > 0 && !this.aircraft.crashed
}
```

AI が地面に当たったら、そこから先は的として数えない。ロックと当たり判定のどちらからも外れる。`damage()` は落ちた瞬間だけ true を返すので、落ちたあとの弾で撃墜数を二重に数えることはない。

**海面ちょうど（高度 0）では落ちない。**トリムでは揚力が重量とつり合うので高度がわずかに正へ動き、`y <= floor` を満たさなくなる。テストは海面より下へ置いて確かめる。

## トリムで置くと 60 秒放っても崩れない

初期条件は水平定常飛行のトリムから解く。`trimCondition(speed, airDensity(altitude))` が迎角とスロットルを返す。開始直後に沈んだり浮いたりすると、そのぶんだけ後の検証がぶれる。

実測で、高度 3,000 m・250 m/s に置いて 60 秒放つと高度 +3.793 m、速度 249.937 m/s。1 分で 3.8 m 浮き、速度は 0.063 m/s 落ちる。

## 描画は複製で増やす。舵面は機ごとに持つ

`glb` は読み直さない。`loadAircraftModel` の結果を `clone()` で増やす。three の `clone()` はジオメトリとマテリアルを参照で共有するので、増えるのはノードの器だけ。

標的機（`targetView.ts`）との違いは舵面が動くこと。標的機は直進か定常旋回しかせず、定常旋回のバンクは中立の舵で保たれるので舵を動かさない。敵機は飛行モデルが舵面の位置を返してくるので、機ごとに別の舵角を反映する。だから複製ごとに `ControlSurfaces` を持ち、舵面のノードは複製の中から名前で引く。元のモデルの `surfaces` を渡すと全機が同じノードを回す。

## 指令加速度を操縦へ写す

飛行機は横へ押されて曲がるのではなく、**揚力の向きを変えて曲がる。**だから「この方向へ加速したい」を操縦へ写すには 2 段が要る。まずロールで揚力の向きを合わせ、それからピッチで引く。実機の操縦と同じ順序。

### ロールの目標は定常旋回のつり合いから出す

    φ_target = atan2(a_h, a_v + g·v̂_y)

`a_h` は指令の水平横成分、`a_v` は鉛直成分。`v̂` は速度に垂直な面の「上」向きで、水平飛行では真上。**要点は分母の重力。**水平飛行では揚力が 1 G を支えている。そこへ横 5 m/s² を足すなら 28 度倒せばよい。

最初は機体座標での指令の向きの角度 `atan2(b.x, b.y)` を目標にしていた。**これは指令が小さいと悪条件になる。**小さな数どうしの比なので向きが定まらない。

実測で、真後ろ 3,000 m の相手を追って**機軸の誤差が 0.5〜0.9 度しかない状態のまま、バンクが ±47 度を 1 秒ごとに往復した。**追尾そのものは成立していたが、敵機が理由もなく揺れる。

| | バンクの振れ幅 | 機軸の誤差 | 高度の変化（24 秒） |
|---|---|---|---|
| 指令の向きの角度 | ±47° | 0.5〜0.9° | −20 m |
| 定常旋回のつり合い | 0.0° | 0.11° | +4 m |

**姿勢の制御が発振したのではなく、参照そのものが暴れていた。**制御の帯や減衰を触っても直らない類の欠陥で、原因は参照の作り方にある。

### ピッチは機体の上成分を旋回率で正規化する

    ω_desired = b.y / v
    pitch = ω_desired / ω_max

`ω_max` は G 制限から決まる `gLimitedPitchRate(v)` と舵の上限の小さいほう。**こう割ると指令が自動で正規化される。**固定の基準加速度で割ると速度によって効きが変わる（高速では同じ G でも角速度が小さい）。

押す側は 0.3 までに絞る。実機の操縦者は持続的な負 G を避ける。ロールで向きを合わせるほうが速い。

要求が小さいときは「経路角を 0 に保つ」指令へ滑らかに混ぜる。ピッチの指令は角速度なので、0 では姿勢が保たれるだけで経路は重力で沈む。実測で 24 秒に 20 m（−0.8 m/s）落ちた。

## 追尾は比例航法と機軸の誤差の和

比例航法は `src/sim/weapons/missile.ts` の純関数をそのまま使う。航法定数もミサイルと同じ 3.5。機体は G の上限が 7.5 でミサイルの 30 よりずっと低いので、大きくしても出せない。

**比例航法だけでは相手を機首に乗せられない。**指令の大きさが視線の回転率に比例するので、遠距離では幾何が崩れていてもほとんど出ない。同速で真横にいる相手には相対速度がほぼ 0 なので出ない。真後ろの相手にも反応しない。

だから機首を相手へ向ける成分を足す。大きさは 機軸からの角度 / 時定数 × 速度。

**1 − cos（角度）では効かない。**小角では θ²/2 なので、20 度の誤差でも 0.06 しか出ない。実測で機軸の誤差は 11.5 度から 31.7 度へ開き続け、G も 1.4 から 2.0 しか出ていなかった。相手の旋回率に負けて後落ちしていた。角度そのものを使うと 20 度で 4.4 G。

### 時定数は振って決めた

3 つの構図で 500 m まで詰める時間と、そのときの機軸の誤差を測った。相手は旋回率 0.04 rad/s か直進で、自機と同速。

| τ | 旋回する相手（後方 3 km） | 直進する相手 | 真横 2 km |
|---|---|---|---|
| 0.4 s | 30.8 s / 3.2° | 32.1 s / 0.8° | 25.3 s / 4.9° |
| 0.6 s | 29.9 s / 5.7° | 31.9 s / 1.1° | 18.4 s / 6.2° |
| 0.7 s | 29.6 s / 6.5° | 31.9 s / 0.6° | 13.8 s / 7.0° |
| 0.8 s | 29.4 s / 7.2° | 31.9 s / 0.8° | 11.1 s / 17.5° |
| 2.0 s | 28.2 s / 14.4° | 31.8 s / 0.2° | 9.6 s / 39.4° |
| 5.0 s | 27.3 s / 23.4° | 31.8 s / 0.4° | 9.2 s / 45.1° |

詰める速さはほとんど変わらないのに、指向は τ で大きく変わる。0.8 秒から真横の構図が 17.5 度へ崩れ、0.6 秒では真横の接近が 18.4 秒へ延びる。**0.7 秒を採った。**

### 角度で重みを付けるのはやめた

2 つの項は狙いが違う。比例航法は会合コース（先回りしてぶつかる）を、機軸の誤差の項は指向（機首を相手に乗せる）を目指す。旋回する相手を後ろから追っているあいだ、この 2 つは逆を向く。

実測で、旋回率 0.04 rad/s の相手を 3,000 m 後方から追ったとき、比例航法が 64.5 m/s²、指向の項が 45.6 m/s² を出して**なす角が 172 度。**打ち消し合って残りが 20.5 m/s²（2.1 G）しかなかった。

そこで「機軸が合っているあいだは比例航法だけにする」形を試した。理屈は通るが、実測では**指向が 37.7 度まで崩れて詰める時間は 1.5 秒しか縮まらなかった。**常に効かせるほうがよい。

### 視線の回転率は収束しない

計画では「視線回転率が終末で 0 へ収束すること」を追尾の指標にする予定だった。**実測で収束しない。**旋回率 0.04 rad/s の相手を後方 3 km から追う構図で、視線の回転率は 0.0006 から 0.06 rad/s へ単調に増える。

距離が詰まるほど同じ横方向の速度差が大きな角速度になるので、幾何としてそうなる。ミサイルは 30 G 出せるので押さえ込めるが、機体は 7.5 G しかない。

機体で見るべきは機軸の誤差のほう。**機銃を撃つには機首が相手に乗っていないといけない。**実測で 11.5 度から 1 秒で 3.9 度へ入り、距離が詰まっても 10 度以内に収まる。

### 3/9 ラインの後ろは水平で回る

相手が真後ろにいるとき、視線の垂直成分をそのまま使うと垂直の反転になる。実測で 7.2 G で引き起こし、高度 3,000 m から 4,215 m まで昇って速度が 250 から 141 m/s へ落ちた。そこから立て直しに入り、相手を 6,000 m 先へ見失った。

水平面内で速度に垂直な向きを取り、相手のいる側へ回る形にした。7.5 G・250 m/s の旋回半径は 857 m なので半周に 10.8 秒かかるが、速度を失わない。実測で最低速度が 215 m/s に留まり、距離が 3,440 m から詰まり直す。

## 速度は距離で決める

**速すぎると曲がれない。**7.5 G の旋回半径は速度の 2 乗で伸びる。高度 3,000 m での実測は 200 m/s で 549 m、250 m/s で 857 m、400 m/s で 2,195 m。

全開のままにすると 60 秒で 446 m/s まで加速し、旋回率が 0.165 rad/s まで落ちる。距離から目標速度を決める。

    want = clamp(275 + (range − 500) × 0.06, 275, 420)

遠ければ速く（追い込む）、近ければコーナー速度寄り（曲がれる）。高度 3,000 m のコーナー速度は 196.1 m/s なので、格闘の目標 275 m/s はその 1.4 倍。余裕を持たせないと、少し引いた瞬間にコーナー速度を割って旋回率が落ちる。

スロットルは目標速度との差に比例させる。中立 0.5 で、誤差 25 m/s で飽和する。

実測での効果。

| | 最高速度 | 3,000 m から 0 m まで | 終末の機軸誤差 |
|---|---|---|---|
| 全開のまま | 446 m/s | 35.3 s | 0.1° |
| 距離で決める | 345 m/s | 42.1 s | 0.1° |

7 秒遅くなるが、格闘の間合いで曲がれるようになる。旋回する相手には 36.9 秒で 0 m まで詰まり、機軸の誤差は 9.1 度に収まる。

## 機銃は先行点へ機首を向ける

追尾（`pursueCommand`）は速度の向きを相手へ寄せる指令だった。**機銃は機首から出る。**機首は迎角のぶん速度より上を向いているので、速度を合わせただけでは弾が下を通る。だから射撃では機首から測った誤差を使う。

先行点は弾道から出る。弾は機体の速度を引き継ぐので、地面から見た初速は `機体速度 + 初速`。相手までの飛行時間 t のあいだに相手は相対速度ぶん動く。

    t = bulletTimeToRange(距離)
    先行点 = 相手の位置 + (相手の速度 − 自機の速度) × t

飛行時間は抗力込みの閉形式が `gun.ts` にある。500 m なら実測 0.561 秒。抗力がなければ 0.485 秒なので、抗力で 16% 伸びる。**先行を入れないと当たらない。**500 m を 240 m/s で横切る相手は、そのあいだに 135 m 動く。

実測での先行量。相手は同速で真後ろから追う構図。

| 距離 | 先行量 | 発射時の機軸誤差 | 想定の外れ |
|---|---|---|---|
| 1,197 m | 86.3 m | 1.83° | 38.3 m |
| 996 m | 74.9 m | 0.38° | 6.7 m |
| 592 m | 32.5 m | 0.55° | 5.7 m |
| 312 m | 10.9 m | 0.43° | 2.3 m |
| 202 m | 6.0 m | 0.37° | 1.3 m |

## 射撃の時定数は追尾より短い

追尾の `ALIGN_TAU` は 0.7 秒だが、その緩さでは当たらない。機銃の散布は 3 mrad（0.17 度）で、機軸が 0.5 度ずれていれば 500 m で 4.4 m 外れる。機体の幅は 11.6 m しかない。

振って決めた。相手は自機で、直進と緩い右旋回（roll 0.2 / pitch 0.12）の 2 通り。40 秒で撃った弾と当たった弾を数えた。

| τ | 直進する自機 | 緩く旋回する自機 | 発射時の誤差の中央値 |
|---|---|---|---|
| 0.15 s | 3.3% | 3.4% | 1.27° / 0.73° |
| 0.25 s | 5.6% | 2.7% | 1.23° / 0.76° |
| 0.30 s | 8.3% | 0.8% | 0.85° / 1.20° |
| 0.35 s | 6.6% | 0.5% | 0.39° / 1.25° |
| 0.40 s | 13.2% | 1.9% | 0.37° / 1.11° |
| 0.45 s | 11.5% | 0.0% | 0.31° / 0.96° |
| 0.50 s | 8.3% | 1.9% | 0.43° / 0.81° |
| 0.70 s | 1.4% | 0.0% | 0.59° / 1.31° |

0.4 秒が頂点。**短くしすぎると悪くなる。**0.25 秒以下では発射時の誤差の中央値が 1.2 度台まで戻る。利得が大きすぎて追尾の輪が振れるため。

この値での手ごたえ。

| 自機の入力 | 敵の発射 | 被弾 | 結果 |
|---|---|---|---|
| 直進 | 456 | 60 | 33.9 秒で撃墜 |
| 緩い右旋回 | 419 | 8 | 生き残る |
| 全開で旋回 | 0 | 0 | 敵が射程に入れない |

**まっすぐ飛べば落ちる、機動すれば生き残る。**全開で旋回すると敵は 1 発も撃てない。速度で振り切られて 1,200 m の射程に入らない。

## バーストで撃つ

押しっぱなしにすると弾がすぐ尽きる。携行 578 発は 100 発/秒で 5.78 秒ぶんしかない。0.6 秒撃って 1.2 秒休むので実効は 33 発/秒、17.5 秒で撃ち切る。

実測で、後方 1,500 m から始めた敵は 12 秒あたりから撃ち始め、35 秒で弾切れになる。**そのあとの敵は無害になる。**弾数の調整は手ごたえの段で決める。

## 回避は相手の視線に垂直な面で全力

追われている側が取るのは、相手の照準を外し続ける機動。視線に垂直な向きへ最大の加速度を出せば、相手の見る角速度がいちばん大きくなる。

    perp = 視線 × 速度       （どちらにも垂直）
    指令 = sign × 200 m/s²

200 m/s² は 20 G で、構造の制限 7.5 G を大きく超える。**AI は制限を持たない。**`applyAoaLimiter` と `gLimitedPitchRate` が機体側で絞る。実測で荷重倍数が 9 未満に収まり、失速もしない。

入る条件は、相手が後方 60 度の円錐の内側で 900 m 以内。**回る向きは入る瞬間に 1 回だけ決める。**途中で変えると照準を外し続けられない。乱数は `World.rng` から引くので、同じシードからは同じ向きになる。

抜けるのは最短 5 秒たってから。7.5 G・250 m/s のブレイクターンは 1 周に 21.5 秒かかるので、4 分の 1 周ぶんは続ける。**短いと出入りを繰り返す。**

効いたことは絵ではなくロックで測る。シーカーの追従限界は機軸から 40 度。実測で、後ろを取ってから 10 秒でロックが外れる（距離ではなく角度で外れる）。

## 自機も撃たれる

敵が撃つようになったので、自機を `Combatant` として扱えないといけなくなった。`Aircraft` に耐久を持たせ、`damage()` で減らす。値は敵機と同じ 60。

耐久が尽きたら `crashed` を立てる。`step` が何もしなくなり、機体はその場で止まる。爆発は `Combat` が出す。

弾の物理は 1 か所に置く。**敵の機銃も `Combat` が進める。**`Enemy` は撃つだけで、当たり判定も `Combat` が持つ。プールは自機の 272 に対して敵は 160。連射しないので足りるが、足りないと古い弾を上書きして曳光弾が途中で消える。

曳光弾の帯は 1 本にまとめて書く。`tracers.update` が弾源の配列を取り、自機と生きている敵機のぶんを順に読む。

実測で、後方 1,500 m から撃たれている絵は曳光弾が 1,001 画素・最大 60 階調。画面の下から中央へ 358 画素伸びる。ドローコールは 124 から 126 へ 2 増える。

## 手ごたえは数値に落としてから調整する

「弱い」「強い」では直せないので、3 つの指標を測った。

**敵が自機の後ろを取るまでの秒数。**自機が直進しているとき、正面 2,500 m から
向かってきた敵は 4.9 秒で後方 60 度の円錐かつ 900 m 以内へ入る。真横 2,000 m
からは 10.7 秒。前方 1,500 m（自機が追う側）からは 71.0 秒。

**自機が撃墜されるまでの秒数。**直進していると後方 1,500 m の敵に 27.3 秒、
後方 800 m なら 16.9 秒、正面 2,500 m から始めても 70.2 秒で落とされる。

**1 対 1 の決着時間。**自動操縦（相手を機首に乗せるだけ）だと 100〜180 秒で
決着しない。**これは自動操縦が最大 G で回り続けるため。**下の曲線が示すよう
に、常時全力で機動する相手には当たらない。人が操縦すればそうはならない。

### 「何か操作すれば無敵」の崖を直した

自機の入力を固定して 60 秒回し、被弾数を測った。4 つの初期配置（後方 1,500 /
900 / 右 1,200 / 左 1,800 m）の平均。

| 自機の機動 | 直す前 | 直したあと |
|---|---|---|
| 直進 | 46.0 | 59.0 |
| ごく緩い旋回（roll 0.1 / pitch 0.06） | 2.5 | 11.8 |
| 緩い旋回（roll 0.2 / pitch 0.12） | 1.5 | 4.5 |
| 中くらいの旋回（roll 0.35 / pitch 0.22） | 1.8 | 3.8 |
| 強い旋回（roll 0.5 / pitch 0.35） | 9.3 | 2.8 |
| 強い旋回 + 全開 | 0.0 | 0.0 |

直す前は崖だった。直進なら 46 発当たるのに、いちばん緩い旋回にした瞬間
2.5 発へ落ちる。しかも 中 1.8 → 強い 9.3 と逆転していて、操作と結果の対応が
読めない。

原因は制御の形。射撃の指令は機首の誤差に比例するだけだったので、**一定の
旋回率を要求される相手には旋回率に比例した定常偏差が残る。**機首は 2 度の
射撃許容角に入るが、その 2 度が 500 m で 17 m の外れになる。

比例航法を先行項として足した。**必要な旋回率そのものを出すので、偏差を先に
埋める。**航法定数は追尾の 3.5 ではなく 0.5。3.5 では会合コースへ寄せる成分が
機首を相手から外して、直進する相手にも当たらなくなる（0%）。

直したあとは単調に減る。**強く機動するほど安全。**操作と結果の対応が読める。

### 射撃の許容角は広げると弱くなる

2 度から 4 / 6 / 10 度へ広げて測った。**直進する自機を落とせなくなった。**

| 許容角 | 直進する自機 | 発射 | 被弾 |
|---|---|---|---|
| 2° | 33.9 秒で撃墜 | 456 | 60 |
| 4° | 落ちず | 578（弾切れ） | 45 |
| 6° | 落ちず | 578（弾切れ） | 45 |
| 10° | 落ちず | 578（弾切れ） | 45 |

解のない射撃に弾を使って撃ち切る。機動する相手への被弾は 0 のまま増えない
ので、広げる意味がない。2 度に戻した。

### 撃たれていることを HUD に出す

**分からないと、まっすぐ飛んでいて突然落ちる。**既にある警告の並び
（CRASH / STALL / G LIMIT / LOW）に `DMG 63%` を足した。

**傷ついたときだけ出す。**無傷なら何も足さないので、既存の HUD の基準画像は
1 画素も変わらない（実測で確認）。

## 自滅しないことを 36 条件で測る

振ったのは 3 つ。高度 4 通り（600 / 1,500 / 3,000 / 8,000 m）、速度 3 通り（120 / 250 / 400 m/s）、相対方位 3 通り（同方向 / 正対 / 直交）。全組み合わせを 60 秒回した。相手は旋回率 0.06 rad/s。3 段で直した。

### 固定の下限では足りない

対地 800 m の固定値では、高度 8,000 m・400 m/s の 2 条件が地面に当たった。立て直しに入ってから衝突までが 2.6 秒しかない。

引き起こしに要る高度は速度と降下角から出せる。全力で引いたときの旋回半径を R = v / ω_max とすると、失う高度はその円弧の垂直方向の分になる。

    Δh = R (1 − cos γ)

400 m/s の R は 2,195 m で、48 度の降下から戻すには 730 m 要る。これを下限に足すと墜落が 0 になった。

### 円弧だけでも足りない

最低対地高度が 124 m まで落ちる条件が残った。**旋回中に降下へ入ると、翼を水平に戻すあいだ引いても機首が上がらない。**`levelAndClimb` が cos(bank) で割り引くので、バンクが残っているうちは効かない。

戻すのに掛かる時間は |φ| / ω_roll + τ_roll。そのあいだ v sin|γ| で沈み続ける。この項を足した。

### 真下を見るだけでは斜面に当たる

それでも 1 条件が墜落した。追跡すると、**対地 927 m を 20 度で上昇していた敵機が 3.5 秒後に地面へ当たっていた。**そのあいだに地形が 28 m から 1,332 m へ立ち上がっている。

| t | 高度 | 地形 | 対地 | 経路角 |
|---|---|---|---|---|
| 49.5 s | 927 m | 28 m | 899 m | +20.0° |
| 51.0 s | 1,134 m | 530 m | 604 m | +20.2° |
| 52.5 s | 1,340 m | 1,138 m | 202 m | +20.1° |
| 53.4 s | 1,470 m | 1,470 m | 0 m | 墜落 |

傾斜は 44 度。400 m/s では上昇率 137 m/s に対して地形の立ち上がりが 373 m/s。**20 度の上昇では逃げられない。**

対地高度は真下の地形しか見ていない。前方 6 秒ぶんの経路上で余裕がいちばん小さい点を測る形にした（6 点、1 点あたり双三次補間 16 タップ）。余裕が下限に対して詰まっているほど目標上昇角を立て、下限の半分で 45 度にする。推力重量比が 0.96 なので短時間なら保てる。

### 結果

| 直した段 | 墜落 | 最低対地高度 |
|---|---|---|
| 固定の下限 800 m | 2 / 36 | 1 m |
| 引き起こしの円弧 | 0 / 36 | 124 m |
| ロール時間ぶんの沈み | 0 / 36 | 166 m |
| 前方 6 秒の余裕 | 0 / 36 | 600 m |

最後の 600 m は低空の条件の開始高度そのままで、一度も下へ切り込んでいない。失速は全条件で 0 秒。`applyAoaLimiter` が機体側で効いているので、AI がフルに引いても失速しない。

## ダメージは段階を持たせる

耐久が減っても落ちるまで何も変わらないと、当てている実感が出ない。

| 割合 | 煙 | 舵の効き |
|---|---|---|
| 1.0〜0.6 | なし | そのまま |
| 0.6〜0.3 | 薄い | そのまま |
| 0.3〜0 | 濃い | 落ちる（下限 0.55） |

**段ではなく傾斜にする。**閾値で切り替えると、1 発当たった瞬間に煙がぼっと出る。1% 刻みで 0.02 以上跳ばないことをテストで固定してある。

**煙が先、効きの低下があと。**先に効きが落ちると、まだ煙も出ていないのに動きが鈍って理由が分からない。

**効きの下限を 0 にはしない。**立て直しができなくなると、撃たれた敵が必ず墜落して撃墜と区別が付かなくなる。`applyAoaLimiter` も効かなくなって失速する。0.55 は「鈍いが飛べる」水準として選んだ値で、耐久 1 まで削った状態で 4 通りの高度を 60 秒回して墜落しないことを確かめた。

舵の効きは `Aircraft.step` の `StepOptions.controlFactor` として渡す。**飛行モデルの側に「ダメージ」という概念は持たせない。**効きが落ちる理由は呼び出し側が決める。

## 煙は太くて濃くないと絵に出ない

履歴は sim が持ち（`DamageSmoke` の `TrailRing`、384 本 = 12.8 秒）、描画は `ribbon.ts` を通す。翼端渦とミサイルの煙と同じ経路。

最初は排気口の径（半幅 0.55 m）と翼端渦とミサイルの中間の濃さ（0.13）から始めた。**絵に出なかった。**傷ついた敵を後方 260 m から見て、`?dmgsmoke=0` との引き算で測った。

| 濃さ | 画素 | 12 階調以上 | 最大 |
|---|---|---|---|
| 0.13 | 436 | 0 | 2 階調 |
| 0.35 | 2,776 | 1 | 12 階調 |
| 0.50 | 3,381 | 3 | 17 階調 |
| 0.70 | 3,999 | 20 | 23 階調 |
| 0.90 | 4,358 | 68 | 27 階調 |

0.13 では最大 2 階調で見えない。0.9 で「煙を引いている」と読める。参考に翼端渦は 1,335 画素・12 階調以上 7 画素・最大 29 階調なので、**面積は渦の 3 倍で峰の高さは同じくらい。**

翼端渦（0.09）やミサイルの煙（0.16）よりずっと大きい値になる理由が 2 つある。

**リボンの alpha は幅方向に三角形の分布で、中心線だけが最大値。**縁は 0 にしてある（硬い帯にしないため）。幅方向に平均すると半分になる。

**合成が線形空間で起きて、そのあとトーンマッピングが圧縮する。**露出 6 の ACES 系なので、暗い色を重ねても表示値の差はそのまま出ない。

幅も 0.55 m では細すぎた。260 m で 2 画素しかなく、濃さを上げても線にしか見えない。1.2 m へ広げ、拡散も 1.2/秒・上限 8 倍（ミサイルの 0.9/秒・6 倍より速い）にした。ロケットの排気は高速で出るので周りの空気とすぐには混ざらないが、燃料の煙は乱流に乗る。

## リボンは新しい端がカメラの後ろにあると全部消えていた

near 面の断面を測る途中で見つけた。**煙を引く相手がすれ違って後方へ抜けると、リボンが丸ごと消える。**

`Ribbon.writePositions` は履歴の添字 0 から順に深度を見て、閾値を割った点で終端していた。添字 0 が閾値の内側だと `{ count: 0 }` を返して何も描かない。

翼端渦では添字 0 が自機の翼端なので必ず前方にあり、ミサイルの煙でも添字 0 がミサイルの位置で前方へ飛んでいく。**この経路は 2 年ぶんの実装で一度も踏まれていなかった。**

ダメージの煙では踏む。相手が正面から来てすれ違うと、添字 0（相手の位置）はカメラの後ろで、その先の古い点は前方に伸びている。実測で、正面 2,000 m から向かってくる敵とすれ違ったあと**差分の画素が 0 になった。**ドローコールは 16 出ているのに絵には何もない。

手前側の点を読み飛ばして、閾値に入るところから始める形に直した。入口も奥の終端と同じく幅と濃さを 0 にする。濃さと経過秒は元の履歴の添字で引くので、何秒前の煙かは読み飛ばしても変わらない。

直したあとの実測（すれ違いのあと）。

| フレーム | 輪郭の画素 | 12 階調以上 | 最悪 |
|---|---|---|---|
| f520 | 1,483 | 15（1.0%） | 27 階調 |
| f600 | 2,535 | 12（0.5%） | 26 階調 |
| f720 | 5,353 | 36（0.7%） | 28 階調 |

見張りは基準画像 `damage-smoke-near`（f720）。この構図で煙の寄与は 104,942 画素・12 階調以上 37,397 画素・最大 110 階調（`?dmgsmoke=0` との引き算）。**欠陥が戻るとここが 0 になる。**E2E ではドローコールでも見る（129 → 145 の 16 本）。

## 煙の断面は出ていない

自機が敵の後ろにつくとカメラが煙の中を通る。台本 `damage-smoke` で、履歴の中ほど（濃さが上限のまま）がカメラのどれだけ近くを通るかを深度から探した。

**フレームは深度から選ぶ。**リボンの古い端は先細りが効いているので、そこを測っても断面は出ない。Phase 5 のミサイルの煙で、発射直後を測って「断面なし」と読み違えた。

実測で f220〜f380 のあいだ、経過 1.1 秒の点が深度 3.4〜4.7 m を通る（near 面の閾値は 7 m）。**機体と軌跡を消して**（`?aircraft=0&trails=0`）測った。

| フレーム | 中ほどの深度 | 輪郭の画素 | 12 階調以上 | 最悪 |
|---|---|---|---|---|
| f220 | 3.96 m | 378 | 3（0.8%） | 15 階調 |
| f300 | 4.69 m | 1,138 | 2（0.2%） | 15 階調 |
| f380 | 3.43 m | 724 | 3（0.4%） | 18 階調 |

比較の基準は翼端渦。対処前が最悪 22 階調、対処後が 4〜5 階調で、Phase 4 の最終形が 1,335 画素・12 階調以上 7 画素（0.5%）・最悪 29 階調。ミサイルの煙は 461 画素・0 画素・6 階調。

**12 階調以上が 0.2〜0.8% しかない。**`blunt2.mjs` の判定は「断面が露出していれば 15 階調以上が並ぶ」で、並んでいない。絵でも、煙は左へ伸びて滑らかに薄れて終わる。

## 1 対 1 を長く回す

自機は素朴な自動操縦で回す。相手を機首に乗せようとするだけの実装で、地形を見ないしエネルギーも管理しない。**AI とは別物にしてある。**同じ実装を両側に使うと、その実装の癖が打ち消し合って検証にならない。

振ったのは高度と初期配置。

高度は 1,500 m / 3,000 m / 6,000 m の 3 通り。

配置は 4 通り。正対 2,500 m。後方 1,500 m。真横 2,000 m。正対の上方 1,200 m。

全 12 条件を 90 秒回した。

**敵は 12 条件すべてで生存。**最低対地高度は 794 m。全条件で 4 つの状態（pursue / attack / evade / recover）が出た。

自機は 2 条件で墜落した。**自動操縦が地形を見ていないため。**AI 側の欠陥ではない。自機の最低対地高度は 1 m まで落ちた。

## LOD が要るかどうか

**F-16 の負荷は三角形ではなくドローコールに出る。**測ってから判断するために数字を並べる。

敵 8 機（`enemy-eight` の台本、frame 240、preset high、SwiftShader）。

| | ドローコール | 三角形 |
|---|---|---|
| 敵なし | 85 | 470,521 |
| 敵 8 機 | 413 | 594,633 |
| 差 | +328（4.9 倍） | +124,112（1.26 倍） |

1 機あたり 41 ドローコール、15,514 三角形。**三角形はシーン予算 1.5M の内側に余裕があるが、ドローコールは基準の 85 に対して 4.9 倍になる。**

計画では「LOD はノードを非表示にするだけで作れる」と見込んでいた。F/A-18C の内訳（翼端ミサイル 8,184 で 43.9%、操縦席の内装 4,602 で 24.7%、外形は 1,956 しかない）から出した見込みで、F-16 では成り立たない。前縁フラップだけで 7,986 三角形（44%）あり、これは翼の輪郭そのものなので落とせない。

外から見えない部品と、近くでしか意味のない部品を隠して、画素の差を数えた。距離は自機からの実測（`lockRange`）。

**吸気口のファン**（`FanR` ほか 6 部品、1,103 三角形、3 ドローコール）だけを隠した場合。

| 142 m 正面 | 0 | 0 階調 |
| 60 m 正面 | 4 | 20 階調 |
| 45 m 側面 | 0 | 0 階調 |
| 174 m 後方 | 0 | 0 階調 |

吸気口の中は 60 m で真正面から覗いたときだけ 4 画素動く。それより遠いと 1 画素も動かない。

**LOD1 の候補をまとめて隠した場合**（ファン 1,103 + キャノピー内側 488 + 塗装デカール 43 + 灯火 48 = 1,682 三角形、13 ドローコール）。

45 m の側面で 183 画素・最大 86 階調。**垂直尾翼の帯とロゴが見える距離。**142 m と 174 m では 4 画素・最大 6 階調しか動かない。

だから 1 段の LOD を距離 100 m 前後で切り替えれば、絵の代償なしに 1 機あたり 13 ドローコール（41 の 32%）と 1,693 三角形（11%）を削れる。敵 8 機で 104 ドローコールと 13,544 三角形。全体では 413 から 309 へ。

### それでも実装は保留にした

**削れることは分かったが、削る必要があるかは分かっていない。**GPU 時間は WSL では測れない（Chromium が Intel Arc を掴まず llvmpipe に落ちる）。手順は `docs/measuring.md`。

### 実機で測って分かったこと

2026-08-24 に実機（Intel Arc 140V / preset high）で `?sweep=1` を回した。**GPU は三角形にほとんど反応しない。**

| 条件 | GPU 最小 | 差 | 三角形 |
|---|---|---|---|
| 基準 | 6.14 ms | — | 474k |
| 地形なし | 5.37 ms | −0.77 ms | 36k |
| 雲なし | 4.02 ms | −2.12 ms | 474k |
| 後処理だけ | 2.75 ms | −3.39 ms | 36k |
| lod 0.65 | 6.09 ms | −0.05 ms | 351k |
| cells 24 | 5.97 ms | −0.17 ms | 282k |

地形を切ると三角形が 92% 減るのに GPU 時間は 12% しか減らない。`cells 24` で 40% 減らしても 0.17 ms。Phase 3.5 の実測（44% 減らして 0.03〜0.05 ms）と同じ傾向。

**この計測に敵機は入っていない。**`?sweep=1` の側に欠陥があった。`runBenchSweep` の `base` に `enemies` が無く、`setMeasureConfig` は `undefined` の項目を触らないので、一度「敵機なし」を通ると二度と戻らない。順番は 1 周ごとにずらすため、最初の周で通った時点から全条件が敵機なしで測られる。

三角形の列でも見分けられなかった。`enemy-eight` から敵 8 機を消すと 599,033 − 8 × 16,184 ≒ 469,561。`level` の 470,521 とほぼ同じで、どちらも 474k と表示される。

直したあとは基準 599k・敵機なし 474k（−125k）に分かれる。埋め忘れは `MeasureToggles` 型で止めた。詳細は `docs/measuring.md`。

敵機ぶんは測り直しが要る。**読むのは CPU の列。**敵 8 機で増えるのはドローコール（85 → 413）で、これは投入側の費用なので CPU 時間に出る。三角形は 26% 増えるが、上の感度から GPU への影響は 0.2 ms 程度と見込まれる。

比較の基準は CPU の最大。この計測では 11.20 ms で、60 fps の予算 16.7 ms に対して 5.5 ms の余裕がある。**敵 8 機で余裕の内側に収まるなら、つまみを作らない。**プリセットに載らない設定項目を作らない規約は、作らないことで満たす。
