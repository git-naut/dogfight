# 飛行モデル

`src/sim/flightModel.ts` と `src/sim/aircraft.ts` の中身を、数式と実装の対応で説明する。係数をいじるときはここを読んでから触る。

飛行機に働く力は推力、揚力、抗力、重力の4つ。このうち揚力と抗力は迎角と速度で決まり、推力はスロットルと空気密度で決まる。アーケード向けの補正を4つ重ねているが、土台の4力は物理そのままにしてある。

## 座標系と状態

右手系、Y が上、機首は -Z。three.js のカメラと同じ向きに揃えてある。

状態は位置、速度、姿勢クォータニオン、body 座標系の角速度、実効スロットルの5つ。長さはメートル、時間は秒、角度はラジアン。

姿勢にオイラー角を使わないのは、機首が真上を向いた瞬間にジンバルロックで破綻するから。空戦では垂直上昇や背面飛行が普通に起きるので、クォータニオンで持つほうが安全になる。

## 動圧

揚力、抗力、舵の効き。いずれも動圧に比例する。

```
q = ½ ρ v²
```

ρ が空気密度、v が対気速度。速度の2乗で効くので、速度が倍になれば揚力と抗力はどちらも4倍になる。実装は `dynamicPressure()`。

## 空気密度

国際標準大気（ISA）で高度から求める。対流圏界面の 11 km を境に式が変わる。

```
h < 11000 :  ρ = 1.225 × (1 - 2.25577e-5 h)^4.2559
h ≥ 11000 :  ρ = ρ11 × exp(-(h - 11000) / 6341.62)
```

対流圏は気温が高度とともに下がり、成層圏は一定になる。温度が一定だと密度は指数関数で減るので、そこで式が切り替わる。6341.62 はスケールハイト `R T / g` で、`287.05 × 216.65 / 9.80665` から出る。

界面での接続値 `ρ11` は定数を書かず、対流圏の式を 11000 で評価して求めている。こうしないと境界に段差が出る。実装は `src/sim/isa.ts` の `airDensity()`。

高度が上がれば揚力、抗力、推力のいずれも落ちる。上空では曲がりにくく加速が鈍い、という飛行ゲームの感覚はこの1本の関数から出てくる。

## 迎角と揚力

迎角は速度ベクトルと機体の向きのずれ。機首が流れより上を向いていれば正。

```
α = asin(-(v̂ · up_body))
```

揚力係数は迎角の折れ線で近似する。

```
|α| ≤ 26°        :  Cl = 4.0 α
26° < |α| < 35°  :  26° から 35° にかけて最大値の 60% まで落ちる
|α| ≥ 35°        :  最大値の 60% で一定
```

揚力傾斜 4.0 /rad は、薄翼理論の 2π にアスペクト比 3.44 の有限翼補正を掛けた値。アスペクト比が小さい主翼ほど傾斜は緩くなる。

失速角を 26 度に置いた理由は下の迎角制限のところで説明する。

揚力の大きさと向きは次のとおり。

```
L    = q S Cl(α)
L̂    = normalize(up_body - v̂ (up_body · v̂))
```

向きに注意が要る。機体上方向へそのまま掛けると、大迎角のときに前後方向の成分が混ざり、推力や制動のように働いてしまう。揚力は定義上つねに速度と直交するので、機体上方向から速度方向の成分を抜いてから正規化する。実装は `liftDirection()`。

## 抗力と誘導抗力

```
Cd = Cd0 + k Cl²
k  = 1 / (π AR e) = 0.1158
```

第1項が有害抗力で、形と表面摩擦から来る。第2項が誘導抗力で、揚力を発生させた代償として必ず付いてくる。翼端で空気が回り込むぶんのロスと考えればよい。AR がアスペクト比、e がオズワルド効率。

この第2項が飛行ゲームの手触りを決める。揚力係数の2乗で効くので、強く引くほど急激に抗力が増える。旋回すると速度が落ちる、という感覚はここから出る。エネルギーを使い切ると曲がれなくなるので、空戦の駆け引きが成立する。

## 推力

```
T = Tmax × throttle × (ρ / ρ0)
```

ジェットエンジンは吸い込む空気の量で推力が決まるので、密度にほぼ比例して落ちる。これで実効的な上昇限度が自然に出る。

## G 制限とコーナー速度

荷重倍数 n で定常旋回するときの角速度は次のようになる。

```
ω = √(n² - 1) g / v
```

構造の制限を 9G としているので、指令ピッチ率の上限も速度から決まる。速度が上がるほど、同じ G で回れる角速度は小さくなる。高速では曲がりにくいという感覚の正体はこれ。実装は `gLimitedPitchRate()`。

一方で、揚力そのものにも上限がある。最大揚力係数で出せる荷重倍数は次のとおり。

```
n_max = q S Cl_max / (m g)
```

低速では揚力が足りず 9G に届かない。2本の制限が交わる速度をコーナー速度と呼ぶ。ここが最も速く回れる点になる。この機体では高度 1000 m で約 172 m/s。実機の F-16 のコーナー速度（350 KIAS 前後）と近い水準になる。

コーナー速度より遅いと揚力不足で曲がれず、速いと G 制限で曲がれない。ドッグファイトで速度を管理する意味はここにある。この関係は `tests/sim/flightModel.test.ts` の二分探索で数値的に確認している。

## 迎角制限器

実機の F-16 はフライバイワイヤで迎角を 25 度に制限している。同じ仕組みを入れてある。制限角の 3 割手前から指令ピッチ率を絞り、制限角でゼロにする。戻す方向の操作は妨げない。

ここで設計上の判断が1つある。当初は失速角を一般的な翼型の 18 度に置いていたが、これだと制限器が働く前に失速してしまい、制限の意味がなくなる。実機の F-16 が 25 度まで引けるのは、前縁付け根の延長（LERX）が作る渦揚力で高迎角まで揚力が伸びるため。そこで失速角を 26 度に上げ、制限器がその手前で効くようにした。最大揚力係数は 1.82 になり、これも LERX を持つ戦闘機として妥当な値に収まる。

失速の表現自体は空力側に残してある。`aoaLimiter: false` を渡せば制限器が外れて失速する。テストはその状態で失速を確認している。

## α と β を分ける

アーケード飛行モデルの定石として「横滑り抑制」が知られている。速度ベクトルを機首方向へ寄せて、機体が横へ流れないようにする処理を指す。

これを素直に実装すると壊れる。速度を機首方向へ丸ごと寄せると迎角がゼロに近づき、揚力が消えてしまう。減衰させてよいのは機体座標系の横方向成分（横滑り角 β）だけで、上下方向の成分は迎角 α そのものなので触ってはいけない。

実装では速度を機体座標へ戻し、X 成分だけを時定数 0.7 秒で減衰させ、また戻している。

```
v_body = q⁻¹ v
v_body.x -= v_body.x × (1 - exp(-dt / 0.7))
v      = q v_body
```

## 風見安定と協調旋回

バンクすると揚力が傾いて飛行経路が曲がる。しかし機首は自動では追従しない。放置すると横滑りが増え続け、上の減衰処理と喧嘩する。

当初の計画では協調旋回のヨー率 `ψ̇ = g tan φ / v` を直接与える予定だった。この式は水平定常旋回でしか正しくないので、引き起こしながらの旋回では機首がずれる。

代わりに実機と同じ機構を入れた。垂直尾翼の風見安定、つまり横滑り角に比例したヨーで機首を経路へ戻す。

```
ω_yaw = 4.0 × β
```

これだけで協調旋回が成立する。バンクすれば揚力が経路を曲げ、機首が遅れて β が生じ、風見が機首を経路へ追従させる。定常状態では小さな β が残るが、これは実機で旋回中にわずかなラダーが要るのと同じ現象になる。式のハードコードではなく機構から出てくるので、どんな旋回でも自然に働く。

ゲイン 4.0 とヨーの時定数 0.3 秒の組み合わせで、減衰比はおよそ 0.46。ダッチロールに似た軽い揺り戻しが残るが、これも実機の挙動に近い。

## 1ステップの処理順

積分は semi-implicit Euler。速度を先に更新し、その速度で位置を進める。素の Euler よりエネルギーの発散が少なく、実装は1行しか変わらない。

1. 指令角速度を作る。舵の効き、G 制限、迎角制限をここで掛ける
2. 風見安定のヨーを足す
3. 角速度を指令へ一次遅れで追従させる
4. 姿勢を積分し、正規化する
5. スロットルを目標へ追従させる
6. 推力、揚力、抗力、重力を合算する
7. 速度を更新する
8. 横滑りを減衰させる
9. 位置を更新し、地面との接触を判定する

姿勢の積分だけは軸角の指数写像で厳密に合成する。微小回転で近似すると角速度が大きいフレームでクォータニオンが伸び縮みする。

```
q ← q × axisAngle(ω̂_body, |ω| dt)
```

body 軸まわりの回転なので右から掛ける。12 万ステップ回しても長さが 1 から 1e-9 以上ずれないことをテストで確認している。

## 一次遅れの書き方

角速度、スロットル、横滑り。いずれも目標へ一次遅れで追従させている。係数を直接掛けるとフレームレートで挙動が変わってしまうので、指数で書く。

```
k = 1 - exp(-dt / τ)
x += (target - x) × k
```

これなら dt が変わっても同じ時定数で収束する。30fps と 480fps で 1 秒後の値が 1% 以内に収まることをテストしている。

## 定数の根拠

F-16 の実測値を基準にした。

| 定数 | 値 | 根拠 |
|---|---|---|
| 質量 | 9,800 kg | 戦闘離陸重量 9,791 kg |
| 主翼面積 | 28.87 m² | 実測値 |
| アスペクト比 | 3.44 | 翼幅 9.96 m の2乗を翼面積で割った値 |
| 最大推力 | 122,770 N | F110-GE-100 のアフターバーナー推力 |
| 揚力傾斜 | 4.0 /rad | 2π にアスペクト比 3.44 の有限翼補正 |
| 失速角 | 26° | LERX による渦揚力を見込んだ値 |
| 有害抗力係数 | 0.020 | クリーン形態 |
| オズワルド効率 | 0.80 | 戦闘機の一般的な値 |
| G 制限 | 9.0 | 構造制限 |
| 迎角制限 | 25° | フライバイワイヤの設定 |

これらから導かれる値が実機の傾向と合うかを、テストで確認している。翼面荷重 3,330 N/m²、推力重量比 1.28、高度 1000 m を 250 m/s で飛ぶときのトリム迎角 1.37 度、コーナー速度 172 m/s。いずれも F-16 級として妥当な範囲に収まる。

## 手触りを調整するとき

`AIRCRAFT` の定数だけを触る。以下が効きの大きい順。

`maxRollRate` を上げると機敏に感じる。既定は 4.0 rad/s で毎秒 229 度。実機の F-16 は毎秒 324 度まで出る。

`rollTau` と `pitchTau` を下げると操作が鋭くなる。既定は 0.12 秒。0.05 秒まで下げるとかなり直結した感触になる。

`gLimit` を上げると高速でも曲がるようになる。物理的な裏付けは薄くなるが、アーケード寄りに振るなら有効。

`cd0` を下げると減速しにくくなり、エネルギーを保ちやすくなる。旋回戦が長引く。

`weathervaneGain` を上げると機首が経路に張り付き、横滑りが減る。上げすぎると揺り戻しが出る。

`FOV_FULL_SPEED` は `src/render/camera.ts` にある。速度感を強めたいときはここを下げる。

## 検証

数値の検証は `tests/sim/flightModel.test.ts`（空力の関数）と `tests/sim/aircraft.test.ts`（積分と操縦）にある。飛行そのものの検証は `tests/replay/scripts.test.ts` で、入力スクリプトを再生して最終状態をアサートしている。

手触りは `npm run dev` に `?debug=1` を付けて確かめる。速度、迎角、G、バンク角が読める。旋回で速度が落ちるか、低速で舵が鈍るか、高速で曲がりにくいか、バンクだけで素直に旋回するか。この4点が数値と体感で一致していれば、モデルは意図どおり動いている。
