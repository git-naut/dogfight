# 実機での計測

WSL からは実機の GPU 性能を測れない。Chromium が Intel Arc を掴まず llvmpipe（CPU ラスタライザ）に落ちるので、出てくる数字は別のものになる。**実機の値は Windows 側の Chrome で読む。**

このファイルは手順の控え。これまでに踏んだ計測の罠も、同じ場所にまとめてある。

## 手順

WSL 側でプレビューサーバを上げる。

```bash
cd /mnt/c/Users/naut8/dev/dogfight
npm run build && npm run preview -- --port 4173 --strictPort --host 0.0.0.0
```

`--host 0.0.0.0` を明示する。既定では WSL の中からしか届かない。

Windows 側の Chrome で開く。WSL2 の IP は `hostname -I` で確認する（`localhost` で届くこともあるが、届かなければ IP を使う）。

```
http://<WSL の IP>:4173/dogfight/?debug=1
```

## 2 つの読み方

ライブループの `?debug=1` では、実際に遊ぶ状態の値が読める。判断は GPU 時間の「最大」で行う。現在値は結果が揃ったときにしか更新されない。重いフレームほど古い軽い値が残る。「GPU 10.8 ms なのに FPS 46」を見て CPU に 11 ms あると読み違えたことがある（Phase 3）。実際の CPU は 0.7 ms だった。

`?sweep=1` は描画の要素を 1 つずつ切って差を測る。1 枚を何度も描くので絶対値はライブループより速く出る。GPU のクロックが上がりきった状態になり、中央値と 3 倍開く。**確定できるのは配分で、絶対値はライブループで読む。**

```
http://<IP>:4173/dogfight/?capture=1&sweep=1&script=weapons-load&frame=240&nodegrade=1
```

`?nodegrade=1` を忘れない。プリセットをまたぐと `maxPixelRatio` も変わる（high 2 / medium 1.5）ので、固定しないと GPU 時間を比較できない。

## 台本を選ぶ

武装を測るなら `weapons-load` を使う。**武装がすべて同時に出ている構図でないと測れない。**標的 2 機・機銃が飛んでいる・ミサイルの煙が伸びている・爆発が出ている、を 1 フレームに揃えてある。実測で f200 以降なら全部出る（f240 なら弾 80 発・煙 30 点・爆発 1 個）。

**どれか 1 つでも出ていないと、その列の差が 0 になる。**0 が出たときに「費用が無視できる」なのか「そもそも描かれていない」なのか区別が付かなくなる。

敵機を測るなら `enemy-eight` を使う。8 機が同時に出ている構図で、実測で三角形が 470,521 から 599,033 へ増え、ドローコールが 85 から 413 へ増える。

**`script` を渡し忘れると `level` になる。**既定値がそれ（`capture.ts` の `params.get('script') ?? 'level'`）。実際に 1 度踏んだ。2026-08-24 の計測で、URL に `script` が入っていなかったために敵機のない構図を測っていた。「敵機なし」の行が基準と同じ三角形数（474k）のままなのが決め手だった。

構図は 1 つで判断しない。海の上と稜線の上では費用の配分がまるで違う（Phase 3.5 の実測）。`low-pass`（低空）と `pull-up`（高 G）も併せて測る。

## 表の読み方

`?sweep=1` の表には 8 列ある。読む順番がある。

**まず「三角形（総数）」を見る。**切った条件で値が動いていなければ、そもそも切れていない。**実際にこれで 1 度騙された。**以前は地形の三角形だけを記録していたので、機体や武装を切っても全条件が同じ数のまま並び、「費用が無視できる」のか「描かれていない」のか区別が付かなかった。

**次に「判定」を見る。**差がばらつきの内側なら「誤差以下」、符号が逆（切ったのに遅い）なら「逆（+N）」と出る。ばらつきの目安は表の下に実測値が出ている（最小値と中央値の差の中央値）。

**「逆」が並んでいたら計測が成立していない。**切ったほうが遅くなるのは物理的にありえない。前回の実機の計測で武装の差が +0.01〜+0.13 ms とすべて正の値で並び、それで気づいた。

**「有意」だけを内訳として読む。**

**GPU の列だけでは足りない条件がある。**この機体構成では GPU は三角形にほとんど反応しない。実測で、地形を切って三角形が 474k から 36k へ 92% 減っても GPU 時間は 0.77 ms（12%）しか減らなかった。Phase 3.5 の実測（地形の三角形を 44% 減らして 0.03〜0.05 ms）と同じ傾向。

**ドローコールが増える条件は CPU の列で読む。**敵 8 機で増えるのはドローコール（85 → 413）で、これは投入側の費用なので CPU 時間に出る。三角形は 26% 増えるが、上の感度から GPU への影響は 0.2 ms 程度と見込まれる。

## 引き算で測るときの作法

遮蔽物を切ると裏のものが代わりに描かれる。海面を切ると隠れていた空のクアッドが描かれ、空の散乱シェーダは海面より高いので逆に遅くなる。「後処理だけ」の床を必ず併せて測る。

**代表値は最小値。**割り込みは時間を増やす方向にしか効かない。平均と中央値は環境の騒がしさを拾う。最小値に替えて初めて部分の和が全体と合った。

1 周ごとに開始位置をずらす。設定ごとにまとめて測ると後半ほど遅く出る。総当たりにしても 1 周内の位置が結果に乗る（法線摂動なしが基準より 228 ms 遅いという値が出た）。`bench.ts` はこれを済ませてある。

サンプル数の比から ms を外挿しない。雲で +31% と見積もって実際は +58% だった。

## 計器が嘘をついた例

キャプチャモードは DPR を 1 に固定している。基準画像を機械に依らせないため。実機は DPR 1.50 で画素数が 2.25 倍あるので、計測モード（`?sweep=1`）だけ実 DPR を使う。

タイマークエリの結果は同じ JavaScript タスクの中では揃わない。`gl.finish()` のあと 10 万回ポーリングしても `QUERY_RESULT_AVAILABLE` が立たない。`requestAnimationFrame` をまたいで回収する。

`gl.finish()` では Chrome の描画は同期しない。`gl.readPixels` で読み戻さないと投入時間しか測れない。全解像度が 1/4 より速いという嘘の値が出た。

## Phase 4 時点の値（比較の基準）

実機 Intel Arc 140V / 1920x997 / DPR 1.50 / high。`?sweep=1` の GPU クエリ最小値。

| 設定 | 高 G（pull-up 430） | 低空（low-pass 2500） |
|---|---|---|
| 基準 | 4.81 ms | 3.40 ms |
| 後処理だけ | 1.73 | 1.45 |
| 雲なし | 2.38 | 2.88 |
| 機体なし | 4.17 | 3.31 |
| 影なし | 4.30 | 3.38 |
| 軌跡なし | 4.31 | 3.40 |

ライブループの最終値は GPU 最大 13.0 ms / 16.7（余裕 3.7 ms）。**武装や敵機を足したあとも、この余裕の内側に収まっていることを確かめる。**

## Phase 6 時点の値

実機 Intel Arc 140V / preset high / `nodegrade=1`。2026-08-24。台本は `level`（敵機は入っていない）。ばらつきの目安は 0.35 ms。

| 設定 | GPU 最小 | 基準との差 | 判定 | 三角形 |
|---|---|---|---|---|
| 基準 | 6.14 ms | — | — | 474k |
| 地形なし | 5.37 ms | −0.77 ms | 有意 | 36k |
| 雲なし | 4.02 ms | −2.12 ms | 有意 | 474k |
| 後処理だけ | 2.75 ms | −3.39 ms | 有意 | 36k |
| 機体なし | 5.91 ms | −0.23 ms | 誤差以下 | 442k |
| lod 0.65 | 6.09 ms | −0.05 ms | 誤差以下 | 351k |
| cells 24 | 5.97 ms | −0.17 ms | 誤差以下 | 282k |

内訳。後処理の連鎖が 2.75 ms、シーン全体が 3.39 ms。そのうち雲が 2.12 ms、地形が 0.77 ms で、残り 0.50 ms がそれ以外の全部。CPU は最小 7.80 ms・最大 11.20 ms。

**Phase 4 の 4.81 ms（高 G）と直接は比べられない。**構図とフレームがどちらも違う。同じ `level` の構図で測り直したときの比較に使う。

敵機ぶんは未計測。次の URL で測り直す。

```
?capture=1&sweep=1&script=enemy-eight&frame=240&nodegrade=1&hour=16
```

## 判断の基準

GPU の最大が 16.7 ms を超えるなら、プリセットの列を下げる。下げる先は実測で決める。**推定で下げない。**「16bit にすると帯域が倍で重くなる」と見込んだことがある。実測では 16bit のほうを速く測った（Phase 3）。
